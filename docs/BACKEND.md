# Workspace backend

This package implements persistent domain services and authenticated actions on the foundation. Product screens are owned by the UI package; an available service does not mean a placeholder screen has been wired. No network service, payment, email, investor contact or live AI provider is used here.

## Public boundaries

`src/features/workspace/actions.ts` exports:

- `readWorkspace()`: `{ok:true,data:WorkspaceRead}` or a typed failure. Returns the current owner's agency, onboarding, draft versions, offers, clients with project history, projects/closeouts, tasks/dependencies, actuals, evidence, immutable calculation snapshots, checklist, saved export manifests and home counts. Dates are ISO UTC strings over the action boundary. New accounts return no agency, empty operational arrays and onboarding next steps. No fixture fallback is used.
- `workspaceCommand({type,input})`: session-derived identity, same-origin mutation validation, bounded input, service authorization, and layout revalidation after a successful write. It returns `{ok:true,data}` or `{ok:false,error:{code,message,fields?,current?}}`. Error codes are `unauthenticated`, `forbidden_or_missing`, `invalid_input`, `conflict`, `rate_limited`, `provider_failed`.

The exact workspace command inputs are exported by `commandSchemas` and `WorkspaceCommand` in `src/features/workspace/contracts.ts`. Finance command inputs are exported by `financeCommandSchemas` and `FinanceCommand` in `src/features/finance/service.ts`. Forms should parse/coerce their own strings, then submit the typed DTO; the server validates again. Empty numeric fields become null, not zero. Money is integer cents for actuals/offers, decimal strings in scenario inputs. USD is the only currency.

`GET /app/exports/[id]?format=markdown|csv` reauthenticates and authorizes the saved snapshot at download time. Responses are attachments with private/no-store, no-sniff and no-referrer headers, including error responses. GET creates no export or calculation snapshot. Export creation and downloads have persistent per-account quotas (10/15 minutes), with an additional trusted-IP quota (50/15 minutes). Proxy trust defaults to zero. These are local single-database controls, not distributed internet abuse protection.

## Persistence and transitions

Services take an injected Prisma client, a trusted session-derived user ID and a clock for tests. They are server-only. Callers must never expose the injected user ID as a browser argument. Every domain call independently checks ownership. Nested references and optimistic versions are checked inside the transaction that writes them. Failures roll back dependent changes. Unique owner/acceptance/export keys and persisted versions provide integrity; unique conflicts are recoverable failures rather than overwrite permission.

Acceptance uses Nolan's canonical `src/lib/ai/contracts.ts`, copied unchanged from the engine contract. A preview does not create an agency. Acceptance copies the exact current generated draft in the same transaction as agency/offers/role-workflow references and nine initially missing data-room categories. Accepted draft versions remain immutable; a later generation cannot replace projects or actuals. A repeated matching acceptance returns the same agency.

Projects progress planned → active → review → completed, with explicit reopening to active. Completion creates no revenue or receipt. Archiving is reversible and keeps related evidence. Archived clients/offers cannot receive new work; existing project references remain intact. Dependency graphs reject self/circular, missing, cross-agency and cross-project edges. Successor unlock is conditional and versioned. Original committed task dates survive rescheduling. Cancellation needs a dated reason. User-assigned work requires an owner transition from awaiting review; crew work must be approved through the saved engine artifact bridge.

Closeout stores delivery date, earned revenue, collections, delivery costs, founder hours/treatment and repeatability separately. Corrections upsert one closeout and one stable evidence reference, then replace the derived month total. Any unknown child amount keeps its derived total unknown. A manual monthly total and project-derived total are never added. Changing source mode requires explicit confirmation. Actual revisions are immutable `FinanceSnapshot` records of kind `actual_revision`; their inputs and provenance survive later edits. Calculation snapshots retain the exact actual/evidence version manifest used to compute them.

Evidence retains origin independently of review status. Revisions cannot relabel sample as user-entered. External-review metadata requires reviewer/date/reference; it is manually supplied, never granted by the demo provider. Safe external references are HTTPS without embedded credentials and are never fetched by the server. Raw text remains inert in React, Markdown exports escape markup, and textual CSV metadata is quoted and protected from spreadsheet formulas.

## Integration with other packages

The shared migration order is `20261121040537_workspace_domains`, then `20261121044853_preserve_cascade_integrity`. The second migration changes immediate RESTRICT references to NO ACTION so deleting a whole owner tree can complete its cascades while direct deletion of referenced clients/tasks is still rejected. The regression covers both behaviors; the first committed migration remains unchanged. It reserves `AgencyEngineState` (user ID primary key, nullable unique agency ID, version, payload) and `AutomationState` (agency ID primary key, version, stateJson). Both cascade with their owning workspace. Avoid independent competing migration baselines. JSON defaults use explicit quoted SQL defaults because the installed Prisma generator emitted invalid unquoted SQLite JSON defaults on the first attempt; fresh migration deployment is tested.

Remy's `createCoreAutomationBridge` projects every automation-owned task/dependency and consumes current saved artifact facts. Direct core task edits are rejected for tasks recorded in AutomationState. Bind Nolan's lifecycle callback to Remy's `recordRunEvent` with the same transaction; do not call `syncTaskApproval` as a second write after automation approval. `syncTaskApproval` exists for non-automation core tasks only. Core `Task`, `TaskDependency`, `ProjectCloseout`, `Client.economicGroupId`, and `ServicePackage.archivedAt` are the agreed SQL contracts.

Engine pitch facts are resolved against owned `EvidenceItem.value.pitchFact` with exact version/provenance matching, or immutable `FinanceSnapshot.output.facts`. Facts use UTC dates while provenance uses timestamps; comparisons use UTC calendar dates. Snapshot facts identify source snapshot/version/formula. Export checks the current generated pitch, rejects superseded versions or changed/foreign facts, and records explicit owner review, selected sources and pitch version in its immutable manifest. No browser-supplied prose is treated as a saved fact.

## Synthetic fixture and reset

Run `npm run db:seed` and then `npm run db:seed:domain`. `db:seed` creates the demo user `seedee-demo-user-v1` (`demo@seedee.local`) and agency `seedee-demo-agency-v1` from the shared `prisma/demo-identity.ts`; the domain seed requires exactly that identity and nonproduction mode. It never adopts another account by email. It atomically marks only that sample workspace, adds explicit sample offers/crew/workflow references, six sample revenue months, structured sample evidence, the computed readiness fixture and three finance scenarios. Historical cash observations stay unknown. A persisted initialization receipt makes repeat seed preserve edits; nonempty uninitialized domain data causes refusal. A demo account created earlier with a generated ID, or by sign-up, is not adopted or relabeled; the domain seed refuses it.

Sample helpers are explicit tooling/fixtures, never a fallback in a real account. User-created agencies keep `sampleWorkspace=false`. The authenticated reset deletes only the owner's marked synthetic domain in a transaction; it preserves the account and other owners. It refuses production and user-entered business evidence. The platform's CLI whole-fixture reset remains its separately guarded operation.
