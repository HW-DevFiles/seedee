# Product UI package

Parker owns the presentation package in `src/features/product-ui`, the app shell, and thin route composition. It builds on `fm/seedee-foundation`. This package is an independently reviewable interface, **not acceptance of the integrated product loop**.

## Current behavior

Account creation/sign-in/sign-out use Theo's real session services. Protected screens reauthorize through `requireUser()`. The adapter reads only the signed-in owner's foundation agency profile. A fresh account has no agency or fabricated traction.

Every named workspace screen has a route, labeled fields, descriptive unavailable/empty states, shared loading and recoverable error boundaries, and navigation to the next relevant view. `?preview=sample` explicitly opts into fictional presentation fixtures; the banner follows every sample view. Sample forms are disabled with a visible reason. Returning to the real workspace does not accept a draft or copy a sample record. Record detail URLs without a connected owned record return not found. Unsupported URLs also return not found.

The package deliberately leaves score, forecast and dilution results uncomputed. It never substitutes Rowan's reference outputs for a calculated snapshot. It includes the exact educational boundary on finance screens, separate provenance/review labels, and the required cash/capacity/founder-pay caveats. All user-provided content renders as React text.

The shared domain packages are not yet in this branch. Their mutation controls visibly explain unavailable persistence. No simulated success, local-storage account database, upload, public share, model request or payment was added. These unavailable actions are an **integration acceptance gap**, not a completed end-to-end demo.

## Binding the services

`contracts.ts` exports presentation-only `WorkspaceUI`, `ScreenView`, `FormSpec`, `Field`, `ActionState` and `FormAction` types. `Screen` accepts the view DTO and an injected form action. It does not authorize records or perform finance arithmetic.

1. Replace the foundation-only mapping in `adapter.ts` with a mapping from Kuba's session-derived `workspace/actions.ts readWorkspace()`. Map only records returned by the owned read; detail views must validate both project and task references. Pass dates, source labels, record IDs and optimistic versions from saved data. Never fall back to fixtures when a real service fails.
2. Bind `productAction` to `workspaceCommand({type,input})`, engine actions and automation boundary commands. Keep an explicit allowlist of command mappings; do not forward an arbitrary browser command. The service must validate/authorize again and create idempotency keys at the appropriate operation boundary.
3. `parseFormInput` converts known form fields, discards unknown owner/user IDs, preserves blank optional values as null, validates supported choices and bounds, and converts dollar strings to integer cents exactly. Domain-specific schemas remain authoritative. Do not feed formatted display amounts into finance functions. `commandState` maps the agreed `{ok,data}|{ok:false,error:{code,message,fields}}` result to field errors, conflict or success. Clear `unavailableReason` only after that operation is connected.
4. Map Nolan's persisted drafts/runs/artifacts/pitches through `agency-engine` service DTOs. Draft acceptance remains Kuba's atomic transaction. Only an approved, current artifact can satisfy review. A generated artifact does not record project delivery.
5. Invoke Remy's `createAutomationBoundary` wrapper. All task lifecycle/deadline operations for automation tasks go through its commands/run bridge. Use `expectedVersion`, `expectedTaskVersion` and persistent idempotency keys. Never directly set the next task to done from the view. Reads are read-only; routine processing is an authenticated mutation.
6. Finance services return display values and exact versioned results from readiness-v1.1, agency-finance-v1.1 and dilution-education-v1.0. Scenarios do not improve historical facts. Populate base/downside/upside, downside without hire, cash deficit, unserved demand, ending mean cash flow, founder-loaded/replacement views, and separate historical/forward receipts-stop measures from those returned results.
7. Create exports by authenticated command, then populate safe owned attachment links to `/app/exports/[id]?format=markdown|csv`. A GET must not create a snapshot. Mixed sample/real actuals remain a service error; offer separate snapshots. The view must not construct a public share URL.

Form IDs in `catalog.ts` document the intended command families. They are UI names, **not a claim that identically named backend commands already exist**. Details such as safe URL validation, review eligibility, unreferenced-draft deletion, archive/reopen rules, evidence reconciliation and reset scope stay in the domain services. Additional per-record forms can be supplied through the same DTOs rather than changing the rendering layer.

## Accessibility and evidence

Controls use hunter/deep green text on off-white/white/sage surfaces. Ochre is decorative. Form controls have a darker boundary token than decorative card borders. Buttons have at least 44px target height. Errors identify fields and focus a linked summary; pending states disable duplicate submission. Success is announced only for an injected successful service result. Tables have captions, row/column headers, a keyboard-focusable scroll region and an explicit narrow-screen scroll label. Reduced motion disables transitions.

Automated UI boundary tests cover exact cents/null semantics, invalid choices/ranges, discarded ownership fields, conflict/rate-limit mapping, read-only fixtures and nested route resolution. Browser tests exercise fresh-account empty states, sample browsing/search/review, sample isolation, protected nested routes, 360px width and keyboard skip navigation. These tests do not assert that currently unavailable domain actions succeed.

Validation commands and observed results are recorded in the delivery handoff after the final build and browser run. Scratch screenshots and local databases live outside the repository under `/private/tmp/seedee-ui-*`.

## Local validation record

The production webpack build, strict typecheck, ESLint, formatting and all 18 unit/database tests passed. Four Chromium tests passed against `E2E_PRODUCTION=1`: the foundation account/session flow plus fresh-account unavailable/unknown states, sample project → task → artifact navigation/search/isolation, and 360px width/keyboard checks. The production test mode is opt-in; default CI behavior is preserved. Test artifacts are written to a temporary directory.

The width check found and fixed a real accessibility-layout defect: absolute screen-reader text inside a wide table escaped the scroll container. Positioning the scroll region keeps the document width at 360px while its table remains 600px and keyboard-scrollable. Mobile navigation collapses behind a button with expanded/control semantics.

Desktop (1440px) and mobile (360px) screenshots were inspected through chrome-devtools-axi against the production build. The browser console was empty, bundled fonts reported loaded, and keyboard focus on Skip to content had a solid 3px outline. Contrast calculations on actual pairs: hunter/off-white 6.90:1; hunter/white 7.46:1; hunter/sage 5.80:1; deep-green/off-white 11.03:1; danger/off-white 7.36:1; control-boundary/white 4.27:1. Text pairs exceed AA and the control boundary exceeds 3:1. These results cover the current fixture/interface package, not the integrated domain loop.

Shared backend contracts were inspected at commit `78ead207b5e73bf18f0763c88e1a38c3d0a35730`; the service implementation was still in progress. Command wrappers, nested pricing/provenance payloads, ISO date conversion, per-record identity/version binding and the live finance/engine/automation mappings remain explicit work for the integration step.
